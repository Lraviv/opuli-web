# תוכנית פיצ'רים v2 — OpuLi

**תאריך:** אוקטובר 2026 · **חל על:** האתר (`opuli-web`: FastAPI + Vite) והאפליקציה (`opu-li`: Expo, SQLite מקומי)

שבעה פיצ'רים: מעקב ממ"נים/ממ"חים, מחשבון ציון סופי, מעקב דרישות תואר, ייצוא ליומן, מסך לו"ז שבועי, קישורים אישיים, ו-skeleton loading. אותה לוגיקה בשתי הפלטפורמות; באתר הנתונים בשרת, באפליקציה ב-SQLite על המכשיר.

---

## 1. מודל נתונים

| טבלה | שינוי | הערות |
|---|---|---|
| `courses` | `exam_weight`, `min_exam_grade`, `min_assignments_count`, `min_assignments_weight`, `assignments_shield` | "כללי הציון" של הקורס. הכול אופציונלי; `exam_weight` ריק = 100 פחות סכום משקלי המטלות |
| `course_items` | `kind` (`mmn` / `mmh` / `other`), `is_mandatory` | רלוונטי למטלות בלבד |
| `degree_requirements` *(חדשה)* | `degree_id`, `category`, `min_credits`, `sort_order` | יעד נ"ז לכל קטגוריה (חובה, בחירה, סמינר...) |
| `links` *(חדשה)* | `course_id` (ריק = קישור כללי למסך הבית), `title`, `url`, `sort_order` | באתר גם `user_id` |
| `class_sessions` *(חדשה)* | `course_id`, `weekday` (0=א'), `start_time`, `end_time`, `title`, `location`, `interval_weeks`, `start_date`, `end_date` | מפגשים קבועים (מפגשי הנחיה הם לרוב פעם בשבועיים, לכן `interval_weeks`) |
| `users` (אתר בלבד) | `calendar_token` | טוקן סודי לכתובת מנוי היומן |

באתר: מיגרציית Alembic אחת. באפליקציה: `addColumnIfMissing` + `CREATE TABLE IF NOT EXISTS`, והטבלאות החדשות נכנסות לגיבוי/שחזור.

## 2. הפיצ'רים

### 2.1 מעקב ממ"נים וממ"חים
**לוגיקה**
- לכל מטלה: סוג (ממ"ן / ממ"ח / אחר), חובה כן/לא, משקל, ציון, תאריך הגשה, הוגש.
- זכאות לבחינה לפי כללי הקורס: מספר מטלות מינימלי ו/או משקל מינימלי שהוגש, וכל מטלות החובה הוגשו.
- סטטוס: ✓ "זכאית לבחינה" / "חסרות עוד X נק' או Y מטלות" / "חסרה מטלת חובה: …".
- יצירת סדרה: "5 ממ"נים החל מ-11" יוצר ממ"ן 11 עד ממ"ן 15 (ממ"ח מתחיל מ-01), עם משקל אחיד אופציונלי.

**UI / UX**
- בראש מדור המטלות: פס התקדמות של משקל שהוגש מול הנדרש, וצ'יפ סטטוס זכאות בצבע.
- בכל שורה: תג סוג, תג "חובה", משקל וציון. מטלה שעבר מועדה ולא הוגשה מסומנת באדום.
- הטופס מציג את שדות הסוג/חובה/משקל/ציון רק למטלות.

### 2.2 מחשבון ציון סופי
**לוגיקה** (פונקציה טהורה, זהה בשתי הפלטפורמות)
- `F(e) = (Σ ציון_מטלה·משקל + e·משקל_בחינה) / (Σ משקלים + משקל_בחינה)`
- מטלה שנבדקה: הציון שלה. שלא נבדקה: ציון משוער (ברירת מחדל: ממוצע המטלות שנבדקו). מסומנת "לא אגיש": 0.
- מגן: `max(e, F(e))`.
- ציון בחינה מתחת לסף (ברירת מחדל 60): הקורס לא עובר, והמחשבון אומר את זה.
- הפוך: "כמה צריך בבחינה כדי לקבל T?". אם התוצאה מעל 100 מוצג "לא ניתן" יחד עם הציון המקסימלי האפשרי. אם מתחת לסף, מוצג הסף.

**UI / UX**
- כרטיס במסך הקורס עם שני מצבים: "מה יהיה הציון" (קלט ציון בחינה) ו"כמה אני צריכה" (קלט יעד). התוצאה גדולה ובולטת.
- לכל מטלה שלא נבדקה יש שדה ציון משוער ומתג "לא אגיש". השדות האלה לא נשמרים, הם תרחיש "מה אם".
- "כללי הציון" נפתחים בתוך הכרטיס לעריכה (משקל בחינה, סף בחינה, מינימום הגשות, מגן).

### 2.3 מעקב דרישות תואר
**לוגיקה**
- לכל קטגוריה: נ"ז שהושלמו, בתהליך ומתוכננים מול הדרישה. ההתאמה נעשית לפי שדה `category` של הקורס.
- "אתחול מהקטלוג" יוצר שורה לכל קטגוריה שבקטלוג. בקטגוריות חובה הדרישה ממולאת אוטומטית כסכום הנ"ז של הקורסים בקטגוריה; בשאר נשאר שדה ריק למילוי לפי הידיעון. לא ממציאים מספרים.
- לכל קטגוריית חובה מוצג גם כמה קורסי חובה עוד לא נבחרו.

**UI / UX**
- כרטיס "דרישות התואר" במסך התואר. לכל קטגוריה פס מחולק לשלושה צבעים (הושלם / בתהליך / מתוכנן) ומספר `x / y`.
- מצב עריכה ברשימה אחת: קטגוריה ונ"ז, הוספה ומחיקה.

### 2.4 ייצוא ליומן
- **אתר:** הורדת קובץ `.ics`, או **מנוי** (כתובת סודית `/calendar/feed/{token}.ics`) שמתעדכן אוטומטית ב-Google Calendar. אפשר ליצור, להעתיק, להחליף ולבטל את הכתובת.
- **אפליקציה:** יצירת `.ics` ושיתוף (Files / Calendar / מייל). סנכרון המבחנים הקיים ליומן המכשיר נשאר כמו שהוא.
- תוכן הקובץ: מבחנים (עם התראה יום לפני), מטלות פתוחות (אירוע של יום שלם בתאריך ההגשה), תזכורות עם תאריך, ומפגשים קבועים (אירוע חוזר).

### 2.5 מסך לו"ז
**לוגיקה:** פריסת המפגשים הקבועים לתאריכים (כולל "כל שבועיים" וטווח תאריכים), יחד עם מבחנים, מטלות להגשה, שיעורים עם תאריך ותזכורות. הכול לפי תאריך **מקומי**.
(בדרך תוקן באג: המסך הקיים חישב את "היום" ב-UTC, אז אחרי 21:00 בישראל הוצג אתמול.)

**UI / UX**
- ניווט: שבוע קודם / היום / שבוע הבא, וכותרת עם טווח התאריכים.
- תצוגת שבוע: יום אחרי יום, לכל יום רשימה כרונולוגית. פריטים עם שעה מופיעים קודם, אחריהם פריטים של יום שלם. פס צבע לפי קורס ותג סוג (מפגש / מבחן / הגשה / תזכורת).
- היום הנוכחי מודגש. מטלה שהוגשה מופיעה מחוקה. לחיצה על פריט מובילה לקורס.
- באפליקציה נשאר גם מצב "חודש" (הלוח הקיים).
- ניהול מפגשים קבועים נמצא במסך הקורס (מדור "מפגשים קבועים").

### 2.6 קישורים אישיים
- קישורים כלליים במסך הבית ("קישורים מהירים") וקישורים לכל קורס בראש מסך הקורס.
- הצעות מוכנות: שאילתא (`sheilta.apps.openu.ac.il`), אופל (`opal.openu.ac.il`), ועוד "הקלטות" ו"מאגר מבחנים" שבהן מוצעת רק הכותרת.
- **אבטחה:** רק כתובות `http(s)`. כתובת בלי פרוטוקול מקבלת `https://`. בשרת ובקליינט נחסמים `javascript:` וכדומה.

### 2.7 Skeleton loading
- רכיב Skeleton עם shimmer, שמכבד את `prefers-reduced-motion`.
- באתר: שלדים לכל מסך במקום "טוען…". אם הטעינה לוקחת יותר מ-4 שניות מוצג "השרת מתעורר… זה יכול לקחת עד דקה" (Render בחינם נרדם).
- באפליקציה: שלדים במסך הבית, בקורס ובלו"ז בזמן הטעינה הראשונה.

## 3. API חדש (אתר)

| Method | Path |
|---|---|
| GET / PUT | `/degrees/{id}/requirements` (PUT מחליף את כל הרשימה) |
| GET / POST | `/links` (`?course_id=` / `?scope=global`) |
| PUT / DELETE | `/links/{id}` |
| GET | `/sessions` · `/courses/{id}/sessions` |
| POST | `/courses/{id}/sessions` |
| PUT / DELETE | `/sessions/{id}` |
| POST | `/courses/{id}/items/batch-assignments` |
| GET | `/calendar.ics` (עם התחברות) |
| POST / DELETE | `/me/calendar-token` |
| GET | `/calendar/feed/{token}.ics` (ציבורי, לפי טוקן) |

מחיקת קורס מוחקת גם את הקישורים והמפגשים שלו. מחיקת תואר מוחקת גם את הדרישות שלו.

## 4. בדיקות
- `pytest` לכל ה-endpoints החדשים: הרשאות (404 למשתמש אחר), ולידציה, ותוכן ה-ICS.
- `alembic upgrade head` על מסד ריק, כדי לוודא שהמיגרציה עובדת.
- לוגיקת המחשבון והלו"ז: בדיקות יחידה על הפונקציות הטהורות.
- אתר: `npm run build` ו-`lint`, ומעבר בדפדפן. אפליקציה: `tsc --noEmit`.
